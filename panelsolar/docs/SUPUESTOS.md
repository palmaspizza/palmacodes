# Supuestos y datos pendientes

- La referencia para el producto es la especificación adjunta y el plan Premium solicitado; la página de propuesta permanece como documento de referencia, no como parte del sitio público.
- No se publicarán información, pantallas o mensajes sobre el desarrollador ni sobre servicios excluidos del alcance.
- La referencia adjunta contiene cuatro variantes del logo. Se adaptó la versión horizontal para la portada y el isotipo sol/panel para navegación, favicon, asistente y panel, conservando el adjunto original sin modificar.
- Hero, imágenes de empresa, galería, productos y OG quedarán como espacios provisionales claramente identificados. No se cargan fotografías de stock ni se atribuyen proyectos o reseñas ficticios a Factor Solar.
- El fondo solicitado con video queda listo para aceptar una URL segura cuando se entregue. Sin video, se muestra una composición gráfica accesible sin imagen de fondo.
- Productos, proyectos y reseñas no tienen datos o fotografías confirmados; por eso empiezan vacíos. No se crean inventarios ni testimonios ficticios.
- La cantidad inicial de técnicos, experiencia, contacto, dirección, horario y cobertura se toma literalmente de la especificación. La cifra de proyectos realizados permanece vacía.
- El catálogo permite hasta 300 productos; el sitio presenta seis productos inicialmente y seis más por tanda después de elegir categorías, mientras el panel presenta 30 registros por página. El filtro público es del lado del navegador y la lectura actual de Firebase aún obtiene la colección completa; por tanto la selección limita la cantidad de fichas e imágenes mostradas, pero no el volumen inicial descargado desde Firebase. Cada producto permite hasta 5 imágenes (principal y cuatro adicionales), pero el panel limita las cargas acumuladas a 100 imágenes/40 MiB estimados; las referencias pueden reutilizar imágenes existentes. Una aplicación estática no puede asegurar por sí sola el consumo mensual de Cloudinary o las descargas de Firebase (también dependen de visitas, imágenes abiertas, transformaciones, límites del proveedor y actividad fuera de este panel). Para reforzar el control se deben configurar restricciones en el preset y revisar el uso en las cuentas; el límite de productos no garantiza por sí solo el consumo.
- Firebase, UID autorizados, dominio definitivo y URL pública siguen pendientes de configuración. El cloud name `dkszomv2f` y el preset `aniquilador` están configurados; se debe verificar que el preset permita las cargas unsigned requeridas antes de publicar.
- Las reglas de ejemplo se entregan solo para `/solar` y no son reglas completas del proyecto compartido. Requieren fusionarse y probarse en el simulador antes de su uso.
- Las funciones que dependen de cuentas externas no pueden probarse en este entorno sin credenciales autorizadas. El sitio tendrá contenido de respaldo para inspección local.
- El logo adaptado se sirve desde un archivo SVG estático local; el campo opcional del panel permite sustituir la marca por una imagen HTTPS.
